## md2docx.py —— Markdown → Word

把目录下所有 `.md` 转成同名 `.docx`，中文公文/作业排版。

```powershell
python md2docx.py <目录> [--author "署名"]
```

| 特点 | 说明 |
|---|---|
| **零依赖** | 纯 Python 标准库，手写 OOXML + zipfile 打包。**不需要** python-docx / pandoc / Word |
| **Python 3.8+** | 你机器上的 3.14 直接能跑 |
| **排版规则** | `#` 大标题（二号宋体加粗居中）、`##` 小节（三号黑体）、正文（三号仿宋，固定行距 28 磅） |
| **缩进约定** | 行首 1~2 个全角空格 → 首行缩进 2 字符；3~5 个 → 左缩进；6+ 个 → 右对齐（落款） |
| **表格** | `\| 表格 \|` → 全边框，表头加粗浅灰底 |

**它不依赖 Word，所以转换过程本身很快**（4 份文档 236 ms）。

> 来源：2026-10-15 一个会话为「桂电草地音乐节文书」任务写的，已实测跑通。
> 署名参数是后加的（原版把作者名写死在脚本里）。

## verify_docx.py —— 验证 .docx（**不要用 Word 验证**）

```powershell
python verify_docx.py <目录> [--expect 关键词1 关键词2 ...]
```

对目录下每个 `.md`，检查同名 `.docx` 是否结构合法、内容完整。**毫秒级，退出码 0=通过**。

| 检查项 | 能查出什么 |
|---|---|
| 包结构 | 必需部件缺失、zip 损坏 |
| XML 合法性 | 每个部件能否被解析 |
| **内容完整性** | 与 `.md` 比对**中文字数与表格数**（逐字对得上才算过） |
| **OOXML 规范** | 子元素顺序错、相邻表格——**Word 对这俩是强校验，但不会报错，只会打开时弹修复** |
| 关键串断言 | `--expect` 传入必须出现的词（活动名、地点等） |

## 为什么不许用 Word 打开来验证（**实测数据**）

2026-10-15 的一次实测：某个会话为了验证 4 份 docx 生成成功，**四次启动 Microsoft Word**，
每次 `Start-Sleep 22` 秒后看标题栏，再杀进程；还试了一次 COM 调用 Word，**卡死 120 秒被移到后台**。

```
四次 Word 验证   102 秒
一次 COM 卡死    120 秒
────────────────────────
合计             约 4 分钟
```

**而这两个脚本加起来 0.4 秒，而且查得更严**（标题栏只能证明"Word 没崩"，证明不了字数对不对、表格数对不对）。

> 更糟的是：那次 Word 明明显示「**受保护的视图**」，脚本却照样判定"文件被正常打开"——
> **说明这个验证手段本身就是不可靠的。**

## sync.ps1 —— 检查工作区落后母版多少

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File sync.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File sync.ps1 -Workspace <工作区根>
```

不传参数就读 `规则系统\已应用工作区.md` 的清单，逐个检查。**只读，不改任何文件。**

它做四件事：

| # | 做什么 |
|---|---|
| 1 | 读工作区 `_同步.md` 的版本号 |
| 2 | 从 `更新日志.md` 挑出「还没跟」的条目，按 ✅自动生效 / ⚠️要手动 / ❌不用管 分类 |
| 3 | 把骨架的「复制型」文件和母版**按结构**对比（章节标题 + 表格行数），列出缺了哪些节 |
| 4 | 输出行动清单 |

**为什么"只看结构"而不是逐字比**：工作区里的 `GLOBAL_WORKFLOW.md` 本来就填过内容
（§0 项目定位、§2 抄的约束），逐字比永远是"有差异"，毫无意义。
**真正要发现的是"母版新增了一节，我这边没有"**——那是结构差异。

## ⚠️ 两个坑（写工具时必踩，记下来）

### 坑 1 · PowerShell 5.1 读 UTF-8 必须带 BOM

**本机是 PowerShell 5.1**（没装 PS7）。它读**不带 BOM** 的 UTF-8 `.ps1` 时会按 **ANSI/GBK** 解析，
**中文全变乱码，脚本直接语法崩溃**：

```
Unexpected token '}' in expression or statement.
```

**规避**：`.ps1` 文件一律存成 **UTF-8 with BOM**。检查方法：

```powershell
(([System.IO.File]::ReadAllBytes($f))[0..2] | ForEach-Object { $_.ToString('x2') }) -join ' '
# 应为 ef bb bf
```

> **注意**：用编辑器工具改完 `.ps1` 后 BOM 可能被吃掉，**改完要复查一次**。

### 坑 2 · 更新日志里必须用代码块和标记隔开"示例"

`更新日志.md` 里既有真条目、又有格式示例，两者长得一样。所以约定：

- 真条目写在 `<!-- ENTRIES -->` 和 `<!-- /ENTRIES -->` 之间
- 示例放在 ` ``` ` 代码块里

**`sync.ps1` 解析时会跳过代码块**。写日志时别把标记写进代码块外。

### 坑 3 · `url.insteadOf` 会让**推送**整个失效（实测）

**症状**：怎么推都是 `504` 或认证失败，但**网页能开、代理正常、仓库也存在**。

**根因**：全局（或本仓库）配了把 `github.com` 重写成镜像站的规则，例如

```
url.https://gitclone.com/github.com/.insteadof = https://github.com/
```

**`gitclone.com` 是只读镜像——它只能下载，不能推送。** 这类重写和推送**天生不能共存**。

**实测结论（2026-10-15，本机 git 2.53 / PS 5.1）**：

| 试法 | 结果 |
|---|---|
| `-c url.<镜像>.insteadof=`（传空值）试图顶掉全局 | ❌ 无效，仍走镜像 |
| 加"更长前缀"的反向映射（把镜像指回 GitHub） | ❌ 无效 |
| 给 remote 单独配 `pushurl`（下载走镜像、推送走正牌） | ❌ **`insteadOf` 把 pushurl 也一起改写** |

**唯一可靠的办法**：**把这类重写摘掉**，下载改走代理。

```powershell
# 摘掉全局重写（先备份！）
copy $env:USERPROFILE\.gitconfig $env:USERPROFILE\.gitconfig.bak
git config --global --unset-all 'url.https://gitclone.com/github.com/.insteadof'
```

> **另一个受害者也可能是 GUI**：GitHub Desktop 读同一份全局配置，
> 所以命令行推不动的时候，**它也一样推不动**。别以为是 GUI 的锅。

### 坑 4 · **git 不读 Windows 系统代理**

**症状**：浏览器能开 GitHub、`Invoke-WebRequest` 走代理也 200，
但 `git push` 报 `Connection was reset` / `Failed to connect to github.com port 443`。

**根因**：**git 不读 Windows 的"系统代理"设置**（`ProxyEnable` / `ProxyServer` 那套）。
它只认自己的 `http.proxy` 配置或环境变量。

**规避**：给仓库配一次（**仓库级，不会进仓库内容**）：

```powershell
cd <仓库>
git config http.proxy  'http://127.0.0.1:7897'    # Clash Verge 默认端口
git config https.proxy 'http://127.0.0.1:7897'
```

**验证**：

```powershell
# 走代理探（应为 200）
Invoke-WebRequest -Uri https://github.com -Method Head -Proxy http://127.0.0.1:7897 -UseBasicParsing
# 确认端口在监听
Get-NetTCPConnection -LocalPort 7897 -State Listen
```

> **注意**：代理端口换了（Clash 改设置、换软件）就要改这两行。
> 项目级的 `http.proxy` 存在 `.git/config` 里，**换机器不会跟着走**，这是对的。

## check-md.ps1 —— 改完 Markdown 后查结构

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File check-md.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File check-md.ps1 -Path <文件或目录>
```

不传参数就查整个规则系统。**只读**，`-Quiet` 只看有问题的。

它查的是**结构**，不查内容对不对：

| 检查项 | 抓什么 |
|---|---|
| **章节编号重复** | 两个 `## 四、`（真发生过） |
| **编号没有递增** | 旧段落插到中间 → 编号回退 |
| **同级同名子标题重复** | 同一个父章节下两个 `### 步骤`（**真发生过**） |
| 代码块 ``` 未闭合 | 少写一个围栏 |
| 表格列数不一致 | 表格某行多/少一列 |
| 空章节 | 叶子标题下面没内容 |
| 占位符没填 `〔…〕` | 只在**模板口径**下查（骨架、`_本工作区.md`、`_同步.md`） |

### 为什么需要它

**改长文档最常见的失败是"替换锚点写窄了、旧内容留在原地"。** 症状：

- 文件是合法 Markdown
- 编辑器不报错
- 工具也不报错
- **只是内容重复了**

**实测案例（2026-10-18）**：改 `00-准备流程.md` 的「附 · 同步」一节，
锚点只包含了标题和引言，**原来那 20 行"步骤"留在了文件末尾**。
结果同一个文件里有两套"怎么同步"，175 行变 196 行。

**关键是：靠"记特征串找回来"查不出这个**——那是查"内容少了"，
而这次是"内容多了"。**必须穷举结构才看得见。**

### 局限（说清楚）

- **查不出"意思变了"**。比如把某条规则改弱了——结构完全正常，检查全过。
  那种**只能靠人读**。
- **对"别人的原文"必然误报**：转录文本（会话记录、第三方 changelog）里的标题不是你的结构，
  跑它只会得到一堆"同级同名标题重复"。**结构检查只对自己产出的文档跑**；要查就跑 `-Path <那个目录>`。
- 表格列数检查会**跳过含内联代码的行**（`` `- <路径> \| derived` `` 里的 `\|` 不是分隔符，
  但精确识别代码跨度太麻烦，跳过更稳）。所以带行内代码的表格**列数不查**。

### 三层配合

```
① 改前读原文件      ← 理解现状
② 改完跑结构检查    ← 抓重复/残留/格式（机械、穷举）
③ 人读关键章节      ← 抓"意思变了"（只能人来）
```

## audit.ps1 —— 规则系统自身的体检

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File audit.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File audit.ps1 -SelfTest
```

**改完母版后跑一次**；`-SelfTest` 先证明检查器自己没坏。只读。

| 检查 | 抓什么 |
|---|---|
| **核心规则行数/字节** | **膨胀**（硬线 170 行，警示 150） |
| 跨文件重复的规则句 | **冗杂** |
| 引用的文件是否存在 | **断链**（排除"待建/举例/泛指"，避免噪音） |
| 核心规则 `§x` 引用 | 引用了不存在的节 |
| **下游工作区的回执格式** | **漂移**（母版五行、下游还是四行） |
| 骨架占位符 | 提醒"这是模板" |
| 必需文件 | 结构缺失 |

**它查不出语义冲突**（两条规则说反话）——那只能靠**发版前全文审一遍**。

> **为什么需要它**：这套系统靠"出事 → 加一条"运转，所以规则会**逐渐变厚**。
> 实测：核心规则从 78 行涨到 **302 行**，其中 24% 是"按需"内容占着"每轮"的位置。
> **没人定期收，它只会越来越重。**

## 用哪个、什么时候用

| 情况 | 做法 |
|---|---|
| 要把 md 转 Word | **直接 `python md2docx.py <目录>`**，别自己写转换器 |
| 转完了要确认没问题 | **`python verify_docx.py <目录> --expect ...`** |
| 需要不同排版（比如论文格式） | 改 `md2docx.py` 顶部的字号/页边距常量，**不要重写** |
| 想知道某个工作区落后母版多少 | **`sync.ps1 -Workspace <工作区根>`** |
| **改完 Markdown、想确认没留下残骸** | **`check-md.ps1 -Path <改过的文件>`** |
| **改完母版规则、想确认没臃肿/断链/漂移** | **`audit.ps1`**（先 `-SelfTest`） |
| **想整体验证模版还灵不灵（不改东西）** | **`selftest-tpl.ps1`**（期望 `14 通过 / 0 失败`） |
| **想知道 AI 会不会真照规则做** | 用 `规则系统\对话测试.md` 手工跑 T1–T4（8 分钟） |
| **收尾时想知道这个对话烧了多少上下文** | **`会话用量.py`**（见下节） |
| 推送失败、报 504 或认证失败 | 看**坑 3** —— 多半是 `url.insteadOf` 把地址改成只读镜像了 |
| 推送失败、报 `Connection was reset` / 连不上 443 | 看**坑 4** —— git 不读系统代理，要单独配 `http.proxy` |

## 会话用量.py —— 这个对话烧了多少上下文

**为什么需要**：模型**自己看不到**上下文用了多少（DSH 不暴露这类环境变量）。
但每次调用的 `usage` 都写在会话日志里，**可以事后读出来**。

**为什么重要**：上下文是**累加**的——每轮都要重新处理全部历史，成本随轮次近似**二次增长**。

| 实测 | |
|---|---|
| 一个长会话 | **53 万 ~ 68 万 token** |
| 开新会话（读几个文件） | **2 ~ 3 万** |

> **差 20 倍以上。而交接只要几百 token，摸索要几万。**

**用法**

```powershell
python 会话用量.py                     # 打印用量
python 会话用量.py --threshold 400000  # 超了返回退出码 1
python 会话用量.py --quiet             # 只打一行
python 会话用量.py --selftest          # 自检（5 项）
```

**口径**：`上下文 = inputTokens + cacheReadTokens`
（**缓存命中部分同样占窗口，必须一起算**——只算 input 会得到"才 184 token"的假象）

**依赖**：`python -m pip install zstandard`

**注意**：
- **它只能"读过去"，不能"预测未来"**——模型没有实时的窗口占用感知
- **它给的是建议，不是自动换会话**。开关在人手上
- 日志有流式增量记录，**别拿日志体积当上下文大小**（实测差 12 倍）
| 不是 Word，是 Excel/PPT | 目前没有工具，需要时再做（`基类\工具\` 就是放这个的） |

## selftest-tpl.ps1 —— 模版自动体检

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File selftest-tpl.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File selftest-tpl.ps1 -SelfTest
powershell -NoProfile -ExecutionPolicy Bypass -File selftest-tpl.ps1 -Keep    # 保留临时目录排查
```

**真搭一个临时工作区、跑全流程、验结果、然后清掉。** 期望 `14 通过 / 0 失败`。

| 阶段 | 验什么 |
|---|---|
| 1 | 骨架复制后文件是否齐（`AGENTS.md`、`GLOBAL_WORKFLOW.md` 各自到位） |
| 2 | **负向**：配置没填时检查工具**会不会报错**（不报才是 bug） |
| 3 | 模拟准备流程，把占位符填掉 |
| 4 | **正向**：填完能否**通过**全部结构检查；"规则完善"四个判据是否真能过 |
| 5 | 登记 → `sync.ps1` 认不认得出 → 注销**干不干净**（比对登记表原文） |
| 6 | **负向**：缺文件能不能被发现 |
| 7 | 临时目录有没有清干净 |

**它测不了什么（必须承认）**：**"AI 拿到规则后会不会照着做"**——那要真开对话。
见 `规则系统\对话测试.md`（T1–T10，逐句可复制 + 判分标准）。
