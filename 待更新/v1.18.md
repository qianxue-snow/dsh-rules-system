# v1.18 · 给下游的变更清单

> 这一版对你**有影响**：新增「开工自检」这个动作。

## 要做的（2 项）

### 1. 在 `_同步.md` 里加一行「母版路径」

```markdown
| 母版路径 | <你的规则系统绝对路径> |
```

**为什么放 `_同步.md`**：因为**所有类型的工作区都有这个文件**（`_本工作区.md` 只有复制型有）。开工自检要靠它找到母版。

### 2. 在开工规则里加「开工自检」

**每次开工，读规则之后、动手之前，先做三步：**

```text
① 读自己 _同步.md 的「模版版本」      → 我 = v1.12
② 读母版的 版本.txt                  → 母版 = v1.18
③ 相等？ → 是：跳过，走正常流程
           → 否：报告给人（见下）
```

**报告长这样**：

```text
【更新检查】我落后 N 版：v1.13 ~ v1.18
清单在 `<母版>\待更新\`，我读了一下，需要做的是：
  · 不变式补齐 6 条（v1.15）
  · 协作模式口径改掉"可选"（v1.15）
  · `_同步.md` 加「母版路径」+ 开工自检（v1.18）
要现在跟吗？
```

**关键：只报告，不自己改。** 等人说「跟」它才动手。

## 为什么这么设计

**没有常驻服务。** 母版不是一个一直在跑的进程，它只在有人改它的时候存在。

所以"通知"只能走这条路：**下游开新会话时自己发现落后 → 告诉人 → 人决定**。

**这也意味着一个物理限制**：**下游不开工，就永远不会知道。** 没有任何机制能叫醒一个没启动的工作区。

## 更新完要做的

1. **跑一次自检**（"重新渲染"）：`check-md.ps1 -Path <你的工作区>`
2. 改 `_同步.md` 的「模版版本」→ `v1.18`
3. 在 `_同步.md` 的「同步历史」记一行：从 → 到、跟了哪些、跳过了哪些
