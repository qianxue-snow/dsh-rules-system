# v1.32 · 给下游的变更清单

> **对你有一项要做**（可选但推荐）：收尾时跑一次 `会话用量.py`。

## 为什么

**模型自己看不到上下文用了多少**（DSH 不暴露这类变量）。
但每次调用的 `usage` 都写在会话日志里，所以能**事后读出来**。

**实测（母版自己的一个长会话）：**

```
53.3 万 token（峰值 67.8 万）
```

**而开新会话只要 2~3 万。差 20 倍以上。**

> 上下文是**累加**的：每轮都要重新处理全部历史，成本随轮次近似**二次增长**。
> **交接只要几百 token，摸索要几万。**

## 新增工具

`基类\工具\会话用量.py`

```powershell
python 会话用量.py                     # 打印用量
python 会话用量.py --threshold 400000  # 超了返回 1
python 会话用量.py --selftest          # 自检
```

**依赖**：`pip install zstandard`

**口径**：`上下文 = inputTokens + cacheReadTokens`
（**缓存命中同样占窗口**，只算 input 会得到"才 184 token"的假象）

## 核心规则 §6 加了一条

> **收尾时跑一次 `工具\会话用量.py`**：超阈值就**建议**换会话
> （**建议，不是自动换**——开关在人）。

## 一个反直觉的发现

**别拿会话日志的体积当上下文大小。**

日志里有**流式增量记录**，实测占 72%——按日志算会得出"1443 万字符"，
而真实上下文是 53 万 token。**差了一个数量级。**
