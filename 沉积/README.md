# 沉积 —— 待提炼的教训

> **暂存区。** 运行中踩到的坑、总结出的约束，先扔这里，别急着改核心规则。
> 攒够了、反复应验了，再升级。升级路径见 `..\README.md` 原则 3。

---

## 怎么用

1. 踩到坑 → 在对应工作区里先解决，同时在本目录新建 `YYYYMMDD-来源.md`
2. 写三件事就够：**什么场景 / 踩了什么 / 该怎么避免**
3. 定期（比如每月）回头看一遍：
   - 同一类坑出现 2～3 次 → 升级进 `..\01-核心规则.md` 或对应基类
   - 只是个别情况 → 留在原地，或直接删

> **判据只有两条：要么升格，要么删。不许无限躺着。**
> **超过 90 天没动 → `audit.ps1` 会提示。**

**这里是「反哺流程」的候选池**（见 `..\反哺流程.md`）：
下游提名上来的、但证据还不够的经验，先落在这里。

---

## 为什么要有这一层

**核心规则每轮都进上下文，有硬预算。** 没验证过的经验不该占每轮成本。

本目录是"缓冲区"：**它让积累变便宜**（随手写一行就行），
**同时给核心规则装了闸门**（只有反复应验的才升得上去）。
