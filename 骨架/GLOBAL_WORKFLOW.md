### 关于「本轮性质」（**别删这一小节**）

它决定新会话**该干什么**，写不清就会出现"它以为要做作业、你以为要验规则"的错位。

| 取值 | AI 该干什么 |
|---|---|
| **正式开工** | 按标准流程做任务：写 input → Plan → Task → 执行 → output |
| **验证系统** | **不要产出交付物**。只跑流程、报告哪里卡手、指出规则本身的缺陷 |
| **纯讨论** | 不动手，只讨论。可以读文件，不写任何产出 |

**不填的后果**（实测过）：新会话只能从材料里猜。它发现 `input\` 是空的，
就老实报告"没有任务可执行"——**它没错，是没人告诉它该扮演什么角色。**

## 3. 标准流程

| 步骤 | 产出位置 | 强制要求 |
|---|---|---|
| 1 需求 Spec | `input\YYYYMMDD-NN-主题.md` | 写清做什么、**为什么做**、验收标准；验收标准必须可判定 |
| 2 方案 Plan | 对话内 | 技术思路、涉及文件、步骤、预期产出、**依据的文件路径**；不明确就先问 |
| 3 拆解 Task | 对话内 | 原子化：改哪个文件、做什么、预期结果；标 `[A]`/`[H]` |
| 4 逐条落实 | 代码/文档 | 按顺序逐条 ✅，禁止顺手改无关部分 |
| 5 变更记录 | `output\` | 固定段模板见第 4 节，并**回填任务看板** |

**改之前先定位**：发现"结果看着不对"时，**先做只读诊断确认根因**，再决定改什么。

> 教训：曾凭"某个数值异常"就断定代码有错，实际代码完全正确，真正原因是配置不同。
> 方向错了，改出来的东西也是错的。

## 4. 产出物契约（`output\` 下固定段）

命名与 input 对应：`YYYYMMDD-NN-主题-报告.md`。正文固定段（顺序不可变，没内容写"无"）：

1. **实际改动摘要**：改了哪些文件、做了什么、产出了什么
2. **数据来源**：每个数字来自哪个文件或哪条命令（**禁止凭记忆填写**）
3. **可信度自检**：样本量是否足够、与历史对比是否异常、**是否出现退化**（全为 0、多组完全相同）
4. **与需求的偏差说明**：未做到的部分、参数被改动的原因
5. **需要人工验证项**（复选框，**必须由人回填结果 + 日期**）
6. **人类练习反馈**（**由人填写，AI 不得代填**）：这次人自己手写了哪些核心逻辑、
   在哪卡住、AI 帮了什么。
   > **学习型项目必填**（`边做边学` / `带教` 模式）；纯交付项目写"（非学习型，跳过）"。
7. **遗留问题与下一步**

> **为什么要有第 6 段**：只记"AI 做了什么"，人翻回去看只知道产出，**看不出自己长了多少本事**。
> 而"我手写了什么、卡在哪"才是能力成长的证据——**这也是 AI 唯一不能替你写的一段。**
